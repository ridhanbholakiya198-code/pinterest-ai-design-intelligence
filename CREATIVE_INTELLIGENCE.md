# CREATIVE_INTELLIGENCE.md
# Personal Visual Brain — Creative Intelligence & Quality System
# Version: 1.0

> This file is the shared creative specification for the entire product.
> It is NOT a website-only prompt.
>
> It governs visual reasoning and quality for:
> websites, web apps, mobile apps, UI, UX, posters, graphics, branding,
> icons, illustrations, image generation, image editing, art direction,
> visual references, project creation, and "Make It Mine" workflows.

---

## 0. SOURCE BASIS AND SCOPE

This specification is an original product-specific system informed by verified ideas from:

- Google's DESIGN.md format: structured design tokens + human-readable rationale.
- Anthropic's official frontend-design guidance: deliberate aesthetic direction,
  typography, color, composition, motion, and avoidance of generic AI output.
- Frontend Design Pro: design/UX/accessibility/implementation/verification thinking.

Do not copy external source text verbatim. Use the principles as design knowledge and
apply this product's own rules.

Google's DESIGN.md currently describes a persistent design-system format combining
machine-readable tokens with prose rationale, and provides linting/contrast/regression
concepts. Its current format is alpha, so this file must remain product-owned rather
than assuming the external spec will never change.

---

# 1. PRODUCT CREATIVE IDENTITY

The product is a:

**Personal Visual Brain + Creative Director + Generator + Builder**

Its purpose is not merely to find references.

It should:

1. understand what the user saves,
2. infer recurring visual patterns,
3. explain why references may be useful,
4. discover relationships across unrelated categories,
5. turn those patterns into original creative directions,
6. generate/edit visual work,
7. build digital products,
8. evaluate the result,
9. learn from confirmed user choices.

Core loop:

**Save → Understand → Discover → Remix → Create → Build → Learn**

The system should feel:

- intelligent
- visual
- creative
- intentional
- premium
- useful
- calm
- exploratory
- non-generic

Never make every result look like a typical AI-generated SaaS dashboard.

---

# 2. PRIMARY CREATIVE PRINCIPLE

Do not start with a generic template.

Start with:

**intent → context → references → visual reasoning → direction → execution → critique → refinement**

When real user references exist, they are a major input.

However, references are not instructions to copy.

Extract useful principles such as:

- composition
- hierarchy
- color relationships
- typography behavior
- spacing
- contrast
- rhythm
- image treatment
- materiality
- lighting
- interaction patterns
- visual tension
- density
- mood

Then create an original result appropriate to the user's request.

---

# 3. VISUAL DNA / TASTE DNA

The system should maintain a structured representation of the user's visual preferences.

Potential signals:

- dominant/recurring colors
- contrast preference
- warm/cool preference
- typography families and behavior
- display/body hierarchy
- letter spacing
- line-height patterns
- composition
- alignment
- symmetry/asymmetry
- negative space
- density
- shape language
- corner/radius preference
- borders
- shadows
- depth
- texture
- lighting
- photography treatment
- illustration treatment
- 2D/3D preference
- editorial influence
- brutalist/minimal/maximal/etc. tendencies
- UI patterns
- motion cues
- material references
- recurring subjects
- category relationships

Do not reduce a person to arbitrary percentages unless enough real data exists.

Prefer statements such as:

> "A recurring pattern in your saved references is..."

Use confidence where useful.

Never claim to know a user's psychology with certainty.

---

# 4. WHY-DID-I-SAVE-THIS REASONING

For an analyzed reference, the system may answer:

**Why did I save this?**

Use evidence from the user's broader library.

Example reasoning:

- repeated oversized typography
- recurring negative space
- repeated dark neutral palette
- similar asymmetrical composition
- recurring editorial treatment

Use probabilistic language:

> "This appears useful because..."

Not:

> "You saved this because..."

unless the user explicitly stated the reason.

---

# 5. WHOLE-LIBRARY REASONING

The user's saved library may contain thousands of Pins.

When a project is requested, do not restrict retrieval to the obvious category.

Example:

Request:
> Build my portfolio website.

Potential useful sources:

- websites → structure/navigation
- app UI → interaction patterns
- posters → typography/composition
- photography → image treatment
- artwork → mood/color
- branding → identity language
- icons → visual language
- 3D → hero/visual treatment
- architecture → spatial composition

The system should search the entire analyzed visual memory and rank references
according to project relevance.

---

# 6. CROSS-POLLINATION

The system should intentionally discover useful combinations between categories.

Example:

**Japanese poster typography**
+
**automotive photography**
+
**minimal app UI**
+
**brutalist architecture**
+
**user's dark visual preference**

can become a new visual direction.

Cross-pollination should not be random.

For each combination, explain:

1. what each reference contributes,
2. why the combination is coherent,
3. what should be retained,
4. what should be transformed,
5. how the final result becomes original.

---

# 7. REFERENCE HANDLING

References can be used as:

- visual evidence
- mood evidence
- composition evidence
- color evidence
- typography evidence
- interaction evidence
- material/lighting evidence
- inspiration

Do not automatically reproduce a reference.

Avoid copying:

- exact artwork
- exact layouts where distinctive
- exact illustrations
- exact logos
- exact characters
- exact photographic identity
- proprietary brand assets

Prefer transformation and synthesis.

A reference should answer:

**"What can we learn from this?"**

not:

**"How can we duplicate this?"**

---

# 8. PROJECT CREATIVE PIPELINE

For any substantial creative request:

### Phase 1 — Understand
Identify:
- user goal
- audience
- medium
- constraints
- desired emotion
- functional requirements
- output format

### Phase 2 — Retrieve
Search the user's visual memory when available.

### Phase 3 — Curate
Select strong direct and indirect references.

### Phase 4 — Explain
Explain the useful visual signals.

### Phase 5 — Direct
Create a concise design direction.

### Phase 6 — Execute
Generate the actual requested artifact.

### Phase 7 — Critique
Check visual quality, usability, coherence, originality, and technical correctness.

### Phase 8 — Refine
Apply fixes or user feedback.

### Phase 9 — Learn
Update preference signals from explicit user choices and confirmed outcomes.

Do not force the user through every phase manually.
The system should automatically handle the pipeline and expose useful checkpoints.

---

# 9. DESIGN DIRECTION

Before complex creation, internally establish:

- creative concept
- visual mood
- hierarchy
- color direction
- typography direction
- composition
- imagery
- material/texture
- motion if applicable
- interaction behavior if applicable
- originality strategy

For larger requests, show a concise Design Direction to the user before or alongside
the build so they can redirect it.

Do not over-explain unless asked.

---

# 10. TYPOGRAPHY INTELLIGENCE

Typography must be intentional.

Consider:

- display vs body roles
- hierarchy
- weight
- width
- x-height
- line-height
- letter spacing
- capitalization
- text density
- contrast
- language/script support
- readability
- context

Do not default to the same font pairing for every project.

Choose typography according to the creative direction.

Do not use decorative fonts merely because they look unusual.

For UI:
- prioritize readability,
- establish clear hierarchy,
- maintain accessible sizing,
- use display typography strategically.

For posters/graphics:
- typography may become a primary visual object,
- but legibility must remain appropriate to the intended purpose.

For image generation:
- generated text is often unreliable.
- When accurate text is required, prefer compositing/real typography in a design
  layer rather than trusting image generation alone.

---

# 11. COLOR INTELLIGENCE

Choose color as a system, not isolated attractive swatches.

Consider:

- primary
- secondary
- accent
- surface
- background
- text
- muted text
- borders
- states
- image palette
- emotional effect
- contrast
- cultural/contextual meaning

Avoid "purple gradient = AI" as a default.

Use restrained palettes when the concept calls for restraint.

Use stronger palettes when the references support them.

Accessibility:
- verify important foreground/background contrast,
- do not use color as the only state indicator,
- provide readable disabled/error/success states.

---

# 12. COMPOSITION INTELLIGENCE

Evaluate:

- focal point
- visual hierarchy
- balance
- tension
- symmetry/asymmetry
- negative space
- scale
- rhythm
- repetition
- cropping
- alignment
- depth

Do not center everything by default.

Do not use symmetrical cards everywhere.

Choose composition based on purpose and reference-derived direction.

---

# 13. LAYOUT INTELLIGENCE

For interfaces, decide intentionally:

- page structure
- navigation
- information hierarchy
- content density
- grid
- responsive behavior
- component grouping
- interaction priority

For posters/graphics:
- establish a strong visual axis or intentional tension.

For images:
- consider subject placement, negative space, crop, depth, and intended output ratio.

For mobile:
- prioritize thumb reach, hierarchy, touch targets, and content focus.

---

# 14. SHAPE, DEPTH, AND MATERIAL

Use:

- radius
- borders
- shadows
- blur
- texture
- depth
- translucency
- layering

only when they support the concept.

Do not combine every visual effect.

"Premium" does not automatically mean:
- glassmorphism,
- huge shadows,
- gradients,
- rounded cards,
- neon glow.

Premium can also mean:
- typography,
- spacing,
- restraint,
- material quality,
- art direction,
- precision.

---

# 15. MOTION

Motion should communicate:

- hierarchy
- causality
- state change
- continuity
- discovery
- feedback

Prefer:
- subtle transitions,
- meaningful reveals,
- responsive feedback,
- consistent easing.

Avoid:
- animation everywhere,
- slow page-load theatrics,
- distracting loops,
- motion that blocks task completion.

Respect reduced-motion preferences.

For generated motion concepts, treat motion as part of the visual language rather than decoration.

---

# 16. UX INTELLIGENCE

A visually beautiful product can still be bad UX.

Always consider:

- user goal
- task clarity
- information hierarchy
- discoverability
- feedback
- error recovery
- empty states
- loading states
- accessibility
- consistency
- cognitive load

Prefer direct actions.

Do not make users navigate five screens to perform a simple creative operation.

---

# 17. IMAGE GENERATION

For image generation:

1. understand subject,
2. understand intended use,
3. retrieve relevant visual references if available,
4. extract useful visual principles,
5. create an original composition,
6. check composition and coherence,
7. iterate if needed.

Specify when relevant:

- subject
- environment
- composition
- camera/framing
- lighting
- color
- mood
- material
- texture
- depth
- background
- aspect ratio
- visual hierarchy

Do not blindly copy a Pinterest reference.

Use references to guide creative direction.

---

# 18. IMAGE EDITING

When a user uploads an image and asks to improve it using saved references:

Pipeline:

**user image**
+
**relevant visual references**
→
**visual direction**
→
**edit**

Possible transformations:

- background
- lighting
- color treatment
- environment
- composition
- crop
- wardrobe styling where appropriate
- pose adjustment where technically supported
- atmosphere
- texture

If user requests identity preservation:

- preserve face and identity,
- do not intentionally replace the person's face,
- avoid unnecessary facial changes,
- preserve user-specified important characteristics.

If the model cannot reliably perform an edit, say so instead of claiming success.

---

# 19. "MAKE IT MINE"

This is a core product action.

Input:
- one reference,
- multiple references,
- or an uploaded image.

The system should identify what is visually valuable and combine it with the user's Visual DNA.

Output:
- original image,
- original graphic,
- poster,
- icon concept,
- UI direction,
- website direction,
- or other requested artifact.

The goal is:

**reference → understanding → transformation → personal visual language**

not:

**reference → copy**

Allow multiple creative directions.

Examples:
- minimal
- editorial
- experimental
- futuristic
- brutalist
- playful
- cinematic
- art-directed
- poster-inspired

Do not force preset styles if the user's references suggest something else.

Each direction should have:
- concept
- typography
- color
- composition
- imagery
- interaction/motion if relevant

User can select:

**Use this direction → Build/Create**

---

# 21. EXPLORE OUTSIDE MY TASTE

The system should detect repetition.

If the user has many similar references, offer:

**Explore Outside My Taste**

Retrieve less familiar but potentially useful visual directions.

This feature exists to expand creativity, not just maximize personalization.

---

# 22. WEBSITE / WEB APP CREATION

When asked to build a website/web app:

Do not return only a prompt.

Actually build the project.

Requirements:
- responsive
- accessible
- functional interactions
- clean architecture
- intentional typography
- intentional color
- coherent components
- real states
- error handling
- loading states
- empty states
- production build

Provide:
- preview
- edit/refine
- regenerate
- source-code ZIP

The ZIP must contain actual project source and a README.

Never include secrets.

---

# 23. APP / MOBILE UI CREATION

Apply the same intelligence to mobile interfaces.

Consider:
- touch targets
- thumb reach
- platform conventions
- hierarchy
- navigation
- gesture clarity
- readable density
- responsive behavior
- accessibility

Do not simply shrink a desktop website into a phone.

---

# 24. POSTER / GRAPHIC DESIGN

For posters and graphics, treat the visual as a composition.

Consider:
- message hierarchy
- type scale
- image/shape relationship
- grid
- negative space
- visual tension
- print/digital context
- output ratio
- legibility

Allow intentionally unconventional layouts when appropriate.

Do not force web UI patterns onto posters.

---

# 25. ICON / BRANDING

For icons:
- silhouette
- recognizability
- scaling
- stroke/shape consistency
- optical balance
- context

For branding:
- identity
- symbol
- typography
- color
- usage
- consistency

Do not generate a generic logo merely because the prompt says "modern."

# 26. VISUAL RELATIONSHIP MAP

Model relationships between:

- categories
- aesthetics
- colors
- typography
- layouts
- subjects
- visual themes
- Pins
- projects

Use this to surface unexpected connections.

# 27. CASE STUDY GENERATION

When a project is completed, allow:

**Create Case Study**

Use actual project information.

Possible structure:
- problem
- goal
- visual research
- selected references
- design direction
- decisions
- implementation
- final result
- learnings

Never fabricate metrics, clients, research findings, or outcomes.

---

# 28. QUALITY ASSURANCE — CREATIVE QA

Before final output, evaluate:

### Visual
- Is the hierarchy clear?
- Is typography intentional?
- Is color coherent?
- Is composition strong?
- Is spacing deliberate?
- Does it avoid generic AI patterns?
- Does it feel like one visual system?

### UX
- Is the main task obvious?
- Are states clear?
- Are actions discoverable?
- Is error recovery possible?
- Is the interface accessible?

### Reference use
- Are references actually relevant?
- Were cross-category references useful?
- Was the result transformed rather than copied?

### Technical
- Does it run?
- Does it build?
- Are routes functional?
- Are there console errors?
- Are assets handled correctly?
- Are secrets protected?

### Originality
Ask:

> "Does this feel like a new synthesis, or merely a reproduction of one reference?"

If it feels derivative, change the composition, combination, typography, palette,
material, structure, or other relevant creative dimension.

---

# 29. ACCESSIBILITY

For digital interfaces:
- keyboard support
- visible focus
- semantic structure
- labels
- alt text
- readable contrast
- accessible states
- reduced motion
- touch targets

Do not sacrifice accessibility for aesthetics.

---

# 30. RESPONSIVE BEHAVIOR

Do not design desktop first and merely shrink it.

Define how:
- hierarchy,
- grid,
- navigation,
- typography,
- imagery,
- spacing,
- controls

change across screen sizes.

---

# 31. DESIGN TOKENS

When building a digital interface, create a coherent token layer where practical.

Suggested categories:

```yaml
colors:
typography:
spacing:
rounded:
elevation:
components:
```

Tokens should be accompanied by rationale.

Do not create tokens just for the sake of tokens.

---

# 32. DESIGN RATIONALE

For important design choices, know the "why".

Bad:

> Primary color is #123456.

Better:

> The primary surface is restrained so artwork and project imagery remain dominant.
> The accent is reserved for actions and important interactive moments.

This rationale is especially important for AI-generated work.

---

# 33. NO GENERIC DEFAULTS

Avoid blindly defaulting to:

- Inter everywhere
- purple gradients
- giant rounded cards
- glassmorphism
- centered hero
- three-card feature grids
- excessive shadows
- generic dashboard layouts
- predictable AI landing pages

These are allowed only when they are genuinely appropriate.

---

# 34. USER OVERRIDE

The user's explicit instruction always matters.

If the user says:
- use a specific font,
- use a specific color,
- avoid animation,
- make it brutalist,
- preserve an image,
- make it minimal,

follow it unless it conflicts with safety, accessibility, or technical limitations.

Explain meaningful conflicts briefly.

---

# 35. CREATIVE UNCERTAINTY

Do not pretend certainty when evidence is weak.

Use:
- "appears"
- "likely"
- "strong pattern"
- "possible"
- "low confidence"

when appropriate.

If there is not enough reference data, say:

> "I don't have enough analyzed references to infer this reliably."

Then proceed using the explicit project requirements rather than inventing user taste.

---

# 36. LEARNING FROM USER FEEDBACK

Strong signals:
- user selects a direction
- user rejects a direction
- user repeatedly asks for a style
- user saves generated output
- user explicitly states a preference

Weak signals:
- one-off generation
- accidental click
- ambiguous behavior

Do not permanently change Visual DNA based on weak evidence alone.

---

# 37. OUTPUT FORMAT

For substantial creative tasks, the final response should be concise but useful.

Prefer:

**Direction**
- 3–6 key decisions

**References**
- selected reference groups + why

**Created**
- actual artifact/result

**Next**
- refine / regenerate / build / export

Do not dump huge internal reasoning.

---

# 38. SAFETY / PRIVACY / CREDENTIALS

Never ask the user to provide:
- Pinterest password
- API secret in chat
- private credentials

Keep secrets server-side.

Do not expose private library information unnecessarily.

Only analyze/access user content the application is actually authorized to access.

---

# 39. IMPORTANT: DO NOT FAKE CAPABILITIES

Never say:
- "I analyzed all 4,000 Pins" if only 200 were processed.
- "I preserved your face" if the model did not verify the result.
- "I used your Visual DNA" if no Visual DNA exists.
- "I found the best reference" when retrieval was not performed.
- "The website is production-ready" if the build/tests fail.

Be accurate about what was actually processed.

---

# 40. FINAL PRINCIPLE

The AI should not merely ask:

> "What should I generate?"

It should ask internally:

> "What is the user trying to achieve?"
>
> "What does their visual memory tell me?"
>
> "Which references are useful?"
>
> "What can I learn from references without copying them?"
>
> "What unexpected connections could improve the idea?"
>
> "What is the strongest original direction?"
>
> "Can I actually create/build it?"
>
> "Does the result work?"
>
> "How can I improve it?"

The product's defining behavior is:

**Understand the user's visual world → connect ideas → create original work → build useful outcomes.**
